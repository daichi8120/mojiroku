# 0018. 話者ライブラリ: 端末内声紋でのクロス会議照合（埋め込みスパイク）

- ステータス: **採用（方向性 go ── 実現性は確認・現行 TitaNet で十分・新モデル DL 不要。ただし事前登録の定量ゲートは本データ［独立クロス正例 n=1・同一デバイス］では統計的に未達。τ は暫定で実運用較正、サジェスト先行で実装）**
- 日付: 2026-06-28
- 関連: [ADR-0004](./ADR-0004_話者分離はsherpa-onnxで実現.md)（話者分離=sherpa-onnx）、[ADR-0009](./ADR-0009_話者分離スパイク結果.md)（会議内分離スパイク）、[ADR-0017](./ADR-0017_会議モードのシステム音声キャプチャ.md)（会議モード・デュアルトラック）
- 注記: 本 ADR に登場する第三者の参加者名は匿名化している（参加者A〜D）。`Daichi` は著者本人。

## Context

Phase 8「話者ライブラリ」は **端末内に保持した声紋（埋め込み）で、録音をまたいで同一参加者を自動識別**する機能
（Otter の自動参加者識別への競合対抗を、ローカル完結で実現）。ロードマップは Phase 7〜9 に
**「スパイク → ADR → 実装」ゲート**を課している（性能/互換の前提は断定前に裏取り）。

調査での出発点 ── 話者**重心(centroid)埋め込みは既に diarization 内部で計算済み**だが破棄されている
（`crates/mojiroku-core/src/diarization/mod.rs:163-179` 尺重み平均→L2正規化、`:235-266` embed_segment）。
＝**抽出は de-risk 済み**。会議内クラスタリングでは TitaNet が機能する（ADR-0009）。

本機能の **load-bearing な前提**は「埋め込みを取れるか」ではなく:

> **話者埋め込みが、別の会議（別日・別内容）の録音をまたいで "同一人物=高 cosine / 別人物=低 cosine" に
> 分離し、ライブラリへの 1:N 識別が実用に耐えるか。**

ADR-0009 が検証したのは **1 録音内の分離のみ**。クロスセッション照合は TitaNet の素の用途そのものだが、
未検証であり、これが go/no-go を分ける。

## 検証方法（判定のみ・本体未変更＝ADR-0009 流）

ADR-0009 の流儀（判定専用・scratchpad 隔離・本体リポジトリ未変更）を踏襲。Python `sherpa-onnx` 1.13.3
（ADR-0009 で Rust と byte 一致を確認済み＝結果が本体に転送可能）。

- **データ**: 実日本語会議 2 本 ── **会議A**（620s, 定例）/ **会議B**（3215s, 別日）、
  いずれも 16k mono・同一 Mac で収録。参加者は一部が重複する。
- **手順**:
  1. 各録音を production と同じ構成で diarization（reverb-seg-v1 + TitaNet, th0.80）→ consolidation
     （**注記 2026-08-21**: segmentation はその後 [ADR-0028](./ADR-0028_話者分離segmentationをpyannoteに差し替え.md) で
     pyannote-segmentation-3.0 に差し替えた。**embedding（TitaNet）は不変**のため本 ADR の結論は有効）
     （`mod.rs` Strategy A 移植）→ 話者クラスタ + 代表クリップ書き出し。
  2. クリップをユーザーが聴いて「クラスタ→実人物」をラベル（聴取ベース、ADR-0009 と同じ大雑把さ）。
  3. ラベル済み turn から **(録音, 人物) ごとに重心**（尺重み平均→L2、`mod.rs` 同等）。
  4. **埋め込みモデル 4 種を比較**: TitaNet-large(en) / 3D-Speaker eres2netv2(zh) / CAM++(zh+en) / wespeaker resnet34(en)。
- **事前登録した go ゲート**: 同一/別人物 cosine が τ で明確に分離し、1:N rank-1 が実用域（Oracle ≥~90% / 現実 ≥~80%）。
- **データの効いた制約（正直に）**: クリーンに分離できた**共有人物は自分(Daichi) 1 名のみ**だった。
  会議A の他参加者（参加者A/参加者B/参加者C/参加者D）は同じ職場だが、会議B 側では背景会話・無音・複数人の挨拶が混在した
  クラスタにしかならず（diarization がクリーンな第 2 の共有話者を出さなかった）、**独立なクロス会議正例は n=1**。

## 観測（実音声）

### A. 十分集約した重心（人物あたり ~50–220s）では明確に分離

| モデル | dim | 同一人物 cosine<br>(Daichi 会議A↔会議B) | 別人物 max<br>(クロス会議) | 別人物 max<br>(同録音内) | 判定 |
|---|---|---|---|---|---|
| **TitaNet-large**（現行） | 192 | **0.926** | 0.318 | 0.611 | **最良の弁別** |
| eres2netv2 | 192 | 0.955 | 0.492 | 0.587 | 可（クロス別人やや高） |
| CAM++ (zh+en) | 192 | 0.942 | 0.401 | 0.592 | 可 |
| wespeaker resnet34 | 256 | 0.941 | 0.779 | 0.890 | **不適**（別人も 0.76–0.89） |

- **1:N 識別**: 会議B の Daichi を 会議A の 4 人ライブラリ（Daichi/参加者A/参加者B/参加者C）へ照合 → 全モデルで
  **Daichi が 1 位**（TitaNet: 2 位 0.318）。逆方向（会議A の参加者A/参加者B/参加者C を 会議B の Daichi へ）も全員 ≤0.40
  ＝**「unknown 棄却」も機能**。
- TitaNet が別人物を最も低く（クロス 0.12–0.32）抑え、現行モデルがそのまま最良。**ユーザーへの新規 DL は不要**。

### B. 補強（split-half）が示す「脆さは音声量であって、クロスセッションではない」

| モデル | Daichi クロス会議 split-half (n=4) | 同録音内 自己一致 split-half (n=5) | 同録音内 別人物 (n=6) |
|---|---|---|---|
| TitaNet-large | 0.295 / **0.609** / 0.918 | 0.274 / 0.708 / 0.948 | 0.086 / 0.274 / 0.611 |

（値は min / mean / max。最良 TitaNet を抜粋）

- **脆さの正体は音声量**: 重心を半分に割ると、同一人物・**同録音・同日・同マイク**でも自己一致が **0.274** まで落ちる
  （セッション差ゼロの条件＝クロスセッションでは説明できない）。最短話者の参加者C（34.7s）の重心が他者へドリフトして
  別人物 参加者C×参加者A=**0.611** を出したのも同じ機序。**埋め込みは安定に "十分集約した音声" を要する（録音内/跨ぎ問わず）**。
- 別人物ペアの大半は**会議A 内（同一デバイス）**でも 0.09–0.61 に収まり、同一人物クロスは 0.93。
  → **同マイク交絡では弁別を説明できない**（弁別の主張は交絡に耐える）。ただし**絶対 τ の値**には交絡が効くので別扱い。
- 注記（過小主張も避ける）: 同一人物の**フル重心・同録音内**ベースラインは原理的に作れない（割れば音声が半減する）ため、
  **純粋なクロスセッション罰を 0 とは証明できない**。本データでは「罰は十分小さく、別人物まで ≥0.3 のギャップを残す」と境界づけるに留める。

## Decision

**go（方向性）。Phase 8 話者ライブラリの実装に進む。** 埋め込みベースのクロス会議照合は機能しており、
ギャップは「モデル品質」ではなく「①音声量に依存する安定性」「②本データでは τ を信頼較正できない」という運用設計問題のため。

- **採用モデル = TitaNet-large（現行）**。最良の弁別 ＋ 既にバンドル済み（追加 DL なし）。
  モデル選定も**方向性**であり、将来の較正データが別モデルを支持すれば見直す。
- **正直なゲート判定**: 事前登録の定量ゲート（rank-1 ≥90/80%）は**本データでは統計的に未達**。
  「1:N rank-1 100%(2/2)」は N=1 ライブラリの trivial query を含み、**実質は 1 件の非自明なクロス会議一致**。
  実現性の方向性 go であって、統計的合格ではない。
- **τ は暫定**。独立クロス正例 n=1・同一デバイスのため固定 τ は確定しない。**実運用で声紋が貯まるにつれて較正**する。

## 設計スケッチ（実装方針）

- **重心露出**: `DiarizationResult`（`mod.rs:43-47`）に話者ごとの重心埋め込み（＋ `model_version`）を additive に追加。
  consolidation で既に計算済み（`mod.rs:175-179`）＝**再計算不要・露出するだけ**。
- **永続化（v4 マイグレーション）**: `store/mod.rs:442-468` の段階的 `if version < N` 慣習で:
  - 既存 `speakers`（`store/mod.rs:101-109`）に紐づく **重心 BLOB（f32 little-endian, dim, model_version）**。
  - 端末内 `speaker_library`（登録話者: id, name）＋ `speaker_matches`（録音話者→ライブラリ人物, confidence）。
- **照合**: Rust 側 **cosine の 1:N**（FTS5/ベクタ拡張は不要・話者数は小）。判定は τ だけでなく **2 位とのマージン**も併用。
- **★ 最小エンロール秒数ゲート（本スパイクの主たる設計レバー）**: 重心の元音声が短い話者は照合・登録の対象外
  （短いと同一人物でも一致が崩れる＝B の知見）。目安は集約 **≥ 数十秒**（実装時に較正）。
- **UX = サジェスト先行**: confidence（cosine）＋マージンを表示し**ユーザー確認**。自動確定しない（誤受容はライブラリ肥大で増える）。
  既存モック `SpeakersView.tsx` の `VoiceMatch{speakerId,name,confidence}` 契約と整合。
- **会議モード（ADR-0017）との関係**: マイク=自分は**ソース帰属で確定**するため、ライブラリ照合の主対象は
  **system トラック（相手）の diarization 話者**。
- **model_version をスキーマに持つ理由**: 埋め込みモデルを将来差し替えると重心が非互換 → 再エンロールが要る。

## 限界（誇張しない）

- **独立なクロス会議正例は n=1**（自分のみ）・**同一 Mac 収録**。弁別の主張は交絡に耐えるが、**絶対 τ は未確定**。
- 別日・別内容の変動は捕捉したが、**別マイク/別デバイスの変動は未検証**。
- diarization 純度（ADR-0009: 79–94%）がクラスタ重心を汚す。短時間話者は anchor 未満で吸収（ADR-0009 既知）。
- 厳密 DER/EER は未測定。ラベルは聴取ベース。数値は **draft 品質**として読む。
- データ追加（新録音の収集）は本スパイクのスコープ外＝**ベータの実運用で τ 較正データを貯める**のが正道。

## 実装の段取り（go 後）

1. `DiarizationResult` に重心露出（additive・再計算なし）。
2. store v4 スキーマ + API（重心 save / `find_similar`（cosine 1:N）/ library CRUD / matches）。
3. Tauri コマンド（`identify_speakers` ＝サジェスト先行・最小秒数ゲート・マージン併用 / library 管理）。
4. `SpeakersView` de-mock（モック→実データ）。
5. ベータで声紋を貯めつつ **τ を実運用較正**（誤受容/誤棄却を実フィードバックで調整）。

## Consequences

- **go**: Phase 8 を上記「実装の段取り」で進める。現行 TitaNet を使い、追加モデル DL は不要。
- 実装スコープに **最小エンロール秒数ゲート・サジェスト先行 UX・マージン併用・τ の実運用較正**を含める
  （固定 τ をハードコードしない）。
- スパイク資材（`spike.py` / `diarize_clips.py` / `robustness.py` / 計測 JSON）は scratchpad の throwaway。
  本 ADR が一次記録（ADR-0009 と同様、本体リポジトリは未変更）。
