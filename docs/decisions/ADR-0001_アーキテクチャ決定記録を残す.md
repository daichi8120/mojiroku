# 0001. アーキテクチャ決定記録（ADR）を残す

- ステータス: 採用
- 日付: 2026-06-24

## Context

mojiroku は dev-hub 初の Rust・初のデスクトップアプリで、技術選定が他プロダクトの前例から外れる。
なぜその選択をしたか（とくに dev-hub 標準の Next.js / Python から外れる根拠）を後から追えるようにしたい。

## Decision

重要なアーキテクチャ判断を ADR として `docs/decisions/ADR-NNNN_*.md` に残す。各 ADR は
**Context / Decision / Consequences** を最小限記述する。番号は連番、過去の ADR は書き換えず、
覆す場合は新しい ADR で「Supersedes NNNN」と記す。

## Consequences

- 選定の経緯と却下案がドキュメント化され、レビュー・引き継ぎが容易になる。
- 記述コストは小さく保つ（1 決定 1 ファイル、数百字）。
